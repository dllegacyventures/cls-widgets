Brew, Git & GitHub — dein Werkzeugkasten.

Drei Werkzeuge, die jeder CLS-Builder einmal einrichtet und dann nie wieder anfasst: Homebrew installiert Programme, Git sichert deine Arbeit, GitHub bringt Kundenseiten ins Netz. Tipp auf die Begriffe — jede Karte erklärt sich selbst.

Die Begriffe in 30 Sekunden

Homebrew (brew)
→ tippen zum Aufklappen
Der App-Store fürs Terminal. Statt Installer-Dateien zu suchen, tippst du brew install <name> — fertig. Updates: brew upgrade.
Git
→ tippen zum Aufklappen
Ein Zeitreise-System für deine Projekte. Jeder „Commit" ist ein Speicherstand. Etwas kaputt gemacht? Zurückspulen. Läuft lokal auf deinem Rechner.
GitHub
→ tippen zum Aufklappen
Die Cloud für Git-Projekte. Deine Speicherstände liegen zusätzlich online — und mit GitHub Pages kannst du eine Kundenseite kostenlos live stellen.
Repository („Repo")
→ tippen zum Aufklappen
Ein Projektordner, den Git überwacht. Ein Kunde = ein Repo. So bleibt jede Webseite sauber getrennt.
Commit
→ tippen zum Aufklappen
Ein Speicherstand mit Notiz, z. B. „Kontaktformular eingebaut". Faustregel: nach jedem fertigen Arbeitsschritt einen Commit.
Push
→ tippen zum Aufklappen
Lädt deine lokalen Commits zu GitHub hoch. Erst nach dem Push ist deine Arbeit online gesichert.

Setup in 4 Schritten

01Git installieren
brew install git
Windows: winget install Git.Git in der PowerShell.
02Git sagen, wer du bist
Steht später in jedem Speicherstand. Einmalig einrichten:
git config --global user.name "Dein Name" git config --global user.email "deine@mail.de"
03GitHub-Konto + CLI
Kostenloses Konto auf github.com anlegen, dann das offizielle Kommandozeilen-Tool verbinden:
brew install gh gh auth login
Bei den Fragen einfach Enter drücken (Standardwerte) und im Browser bestätigen.
04Dein erstes Kunden-Repo
Im Projektordner der Kundenseite (z. B. baeckerei-sommer/):
git init git add . git commit -m "Erste Version der Webseite" gh repo create baeckerei-sommer --private --source=. --push

Der Alltag — immer derselbe Loop

Änderung machen→git add .→git commit -m "was ich getan habe"→git push↺
Merksatz: Commit = Speicherstand auf deinem Rechner. Push = Backup in der Cloud. Wer pusht, verliert nie Arbeit — auch nicht, wenn der Laptop stirbt.

Häufige Stolperer

„fatal: not a git repository"
Du bist im falschen Ordner. Mit cd pfad/zum/projekt in den Projektordner wechseln — dort, wo git init ausgeführt wurde.
„permission denied" beim Push
Login abgelaufen oder nie verbunden: einmal gh auth login ausführen und im Browser bestätigen.
Ich habe etwas kaputt gemacht und will zurück
Alle ungesicherten Änderungen verwerfen: git checkout -- . — du bist zurück beim letzten Commit. Genau dafür macht man Speicherstände.
Muss der Kunde GitHub verstehen?
Nein. GitHub ist dein internes Werkzeug. Der Kunde bekommt eine fertige Webseite und einen Link — mehr sieht er nie.
